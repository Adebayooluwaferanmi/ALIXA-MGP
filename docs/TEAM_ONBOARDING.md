# New-team-member onboarding

## First hour
Read README, PRD, Architecture, Roadmap and ADR-0001. Identify intended workstream and its phase. Review GitHub issues before creating new work.

## First day
Join kickoff, confirm responsibilities and dependencies, understand ALIXA vs ALMS product naming, learn current ALMS render integration and why video data must not force application deployments. Ask for workspace access through secure process; never copy credentials into issues.

## First week
Agree first scoped issue, document expected demo/test, review threat model, inspect contracts and source/revision model, submit small PR. Record uncertainties in issue and architecture choices in ADRs.

## Coordination
Weekly triage; biweekly demo; phase gate reviews. Definition of ready: owner, desired behavior, measurable acceptance criteria, dependencies, security/privacy and rough resource budget. Definition of done: tests, review, docs, rollback and observability when applicable.

## What is built today?
The **existing ALMS Remotion renderer** is deployed elsewhere; this ALIXA-MGP repository begins as a project charter and planning baseline, not a working Media Studio application. Never claim production features are implemented until merged, tested and demonstrated.
